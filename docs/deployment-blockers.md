## Provider documentation review

Current official developer pages were fetched read-only on 10 November 2026. The web text gateway returned 429 for some pages; direct HTTPS retrieval of the following official pages succeeded. No provider event endpoint was called.

- [Pixel consent controls](https://developers.facebook.com/documentation/meta-pixel/implementation/gdpr): revoke before initialization and apply the consent choice per document. The application additionally withholds the SDK until its own eligibility and grant checks pass.
- [Advanced Pixel configuration](https://developers.facebook.com/documentation/meta-pixel/advanced): `autoConfig` can be disabled before initialization. This setting is not proof of source eligibility or isolation from every future SDK feature.
- [CAPI getting started](https://developers.facebook.com/documentation/ads-commerce/conversions-api/get-started): a dataset/Pixel ID and access token are required. The documented direct Events Manager token path does not require a separate App Review/permission request. Do not invent such a universal approval workflow; other integration paths may have their own prerequisites.
- [Using the API and Test Events](https://developers.facebook.com/documentation/ads-commerce/conversions-api/using-the-api): a test-event code labels testing but does not isolate production reporting; these events can still be used for targeting and measurement. Use a separate permitted non-production dataset.
- [Server event parameters](https://developers.facebook.com/documentation/ads-commerce/conversions-api/parameters/server-event): retain the real event time and truthful action source; website events require appropriate source and customer context. The application never replaces a private source with a public landing URL.
- [Deduplication](https://developers.facebook.com/documentation/ads-commerce/conversions-api/deduplicate-pixel-and-server-events): corresponding event names/IDs and dataset must agree. Retry reuses the original opaque ID. Application uniqueness and mock acknowledgement do not prove Meta deduplication.

The actual dataset's categories, account restrictions, event blocking, ownership, automatic settings, traffic permissions and diagnostics remain account evidence for M1–M4. A generic help page, internal denied flag or configured Pixel ID cannot answer those questions. CAPI cannot be used to bypass restrictions that apply to the data source.
